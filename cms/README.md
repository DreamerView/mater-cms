Версия: **2026.09.11.20**

Лёгкая headless CMS на **PHP + Vue 3 SPA** без npm, Vite и build-step. Для хранения данных можно выбрать **SQLite, MySQL или PostgreSQL**.

На мобильных устройствах боковое меню теперь используется только для навигации по основным разделам MaterCMS. Дерево пользовательских папок «Мой контент» и отдельная кнопка **«Новая папка»** из drawer удалены; создание и управление папками выполняются непосредственно на странице **Мой контент**.

Глобальная кнопка **API** удалена из header MaterCMS. Верхняя панель теперь отвечает только за основную навигацию, универсальный поиск и аккаунт пользователя; API по-прежнему открывается из контекста конкретной папки, раздела, набора данных или формы, а общие параметры находятся в **Настройки → Доступ к API**.

## Основная модель

```text
Проект → Контент / Данные / Формы / Файлы → JSON API
```

Каждый проект получает собственный API namespace. MaterCMS сам выбирает способ маршрутизации под web-сервер.

На **Apache/LiteSpeed** используются clean URL:

```text
GET  https://example.com/cms/api/{project-slug}/
GET  https://example.com/cms/api/{project-slug}/{folder}          # рекурсивное дерево папки
GET  https://example.com/cms/api/{project-slug}/{folder}/{section}
GET  https://example.com/cms/api/{project-slug}/data/{data-slug}
POST https://example.com/cms/api/{project-slug}/forms/{form-slug}
```

На **nginx и других серверах без `.htaccess` rewrite** MaterCMS автоматически показывает совместимый direct URL:

```text
GET  https://example.com/cms/api/index.php?path={project-slug}
GET  https://example.com/cms/api/index.php?path={project-slug}/{folder}          # рекурсивное дерево папки
GET  https://example.com/cms/api/index.php?path={project-slug}/{folder}/{section}
GET  https://example.com/cms/api/index.php?path={project-slug}/data/{data-slug}
POST https://example.com/cms/api/index.php?path={project-slug}/forms/{form-slug}
```

API offcanvas, AI Prompt и копирование endpoint всегда используют фактически рабочий URL для текущего сервера.

В **Настройки → Доступ к API** проект можно сделать:

- **Публичным** — без авторизации;
- **Приватным** — каждый запрос требует `Authorization: Bearer <token>`.

Приватный токен генерируется MaterCMS, показывается один раз и хранится в выбранной базе только в виде SHA-256 хэша. Для server-side интеграций используйте переменную окружения `MATERCMS_API_TOKEN`.

> Не вставляйте секретный токен в Vue/React/browser JavaScript или HTML. Для приватного API используйте backend/serverless proxy.

### Формат ответа API

В **Настройки → Доступ к API** отдельно настраивается формат ответа проекта:

- **Только данные** — GET разделов и данных возвращает чистый JSON object/array, а успешный POST формы — только `ok` и `message`;
- **Полный ответ** — GET возвращает объект `{ data, meta }`, а успешный POST формы дополнительно возвращает `submission_id`, `project` и `form`.

Выбор хранится **на сервере отдельно для каждого проекта** и автоматически используется всеми API-панелями. Для совместимости один конкретный запрос можно переопределить через `?meta=1` или `?meta=0`. Корневой `GET /api/{project-slug}/` всегда остаётся картой доступных endpoint проекта.

Во всех API offcanvas есть закрытый по умолчанию spoiler **«Какой ответ вернёт API»** с JSON-примером фактической структуры ответа.

### API папок и временное отключение endpoint

Каждая обычная папка в **Мой контент** имеет собственный GET endpoint и всегда возвращает **всю включённую структуру ветки рекурсивно**: вложенные папки находятся в `folders`, разделы — в `sections`. Отдельные настройки глубины, `include_data` и ручного скрытия веток больше не используются — структура MaterCMS сама является структурой API.

Проектный **Формат ответа** определяет вес Folder API:

- **Только данные** — возвращается всё дерево папок и разделов как информационная структура (`type`, `name`, `slug`, `mode`, `path`, `url`), но без поля `data` внутри разделов;
- **Полный ответ** — возвращается всё дерево вместе с полным содержимым каждого раздела, а ответ дополнительно оборачивается в `{ data, meta }`.

Для каждой папки остаётся только одна отдельная настройка — **кеш готового JSON**: выключен, 30 секунд, 1 минута, 5 минут, 15 минут или 1 час. Если доступен APCu, MaterCMS использует его как RAM-cache; иначе автоматически работает файловый fallback. Кеш разделён для компактного структурного и полного ответа и инвалидируется после изменений через админку.

Для проекта и каждой API-сущности можно независимо включать/выключать внешний API: **проект целиком, папка, раздел, набор Данные и форма**. Выключенный endpoint остаётся настроенным, но снаружи отвечает `404`; данные не удаляются. В Folder API попадают только объекты с включённым собственным API.

В полном ответе `meta.cache` сообщает состояние server-side кеша. Public Folder API также отправляет `X-MaterCMS-Tree-Cache: HIT|MISS|BYPASS` и `X-MaterCMS-Tree-Content: FULL|STRUCTURE`.

- несколько проектов;

- мультиязычность;

- Vue SPA без перезагрузки страниц.

### Поддерживаемые СУБД

- SQLite через `pdo_sqlite`;
- MySQL 8+ через `pdo_mysql`;
- PostgreSQL 12+ через `pdo_pgsql`.

При первом запуске MaterCMS показывает только реально доступные в PHP драйверы, проверяет соединение и только после успешной проверки сохраняет серверный конфиг. Для MySQL/PostgreSQL первым открывается режим **URL**, при необходимости можно переключиться на отдельные поля.

После установки владелец может безопасно сменить СУБД через отдельную страницу **Настройки → База данных**. MaterCMS переносит данные в целевую БД, проверяет результат и лишь затем меняет конфигурацию.

## Установка

Скопируйте папку `cms` рядом с основным сайтом и откройте:

```text
https://example.com/cms/
```

Требования: PHP 8.1+, PDO и хотя бы один драйвер (`pdo_sqlite`, `pdo_mysql` или `pdo_pgsql`), `fileinfo`, права на запись для `cms/data/` и `cms/uploads/`. `mod_rewrite` нужен только если вы хотите clean API URL на Apache; для nginx MaterCMS автоматически использует direct routing без rewrite.

При первом запуске MaterCMS сам проверяет доступные PDO-драйверы. Для MySQL/PostgreSQL можно подключиться через отдельные поля или единый URL. Перед сохранением конфигурации соединение проверяется автоматически.


### Единый интерфейс

Авторизация и первый запуск используют минималистичный широкоформатный интерфейс MaterCMS. В версии **2026.09.11.18** desktop-авторизация дополнительно сбалансирована для Windows с масштабированием интерфейса: левая продуктовая зона больше не сжимается до неестественно узкой колонки, форма получила более спокойную читаемую ширину, а дублирующий мобильный wordmark гарантированно скрыт на desktop. Главная страница настроек содержит прямые переходы **Доступ к API, Языки проекта, Проекты, Команда, База данных** без служебной нумерации. Каждый раздел открывается на отдельной странице. В настройках также доступна тема `Системная / Светлая / Тёмная`.

## Связь между данными

В разделе **Данные** доступно поле **Связь**: оно связывает одну или несколько записей одного набора `Multiple` с другим набором `Multiple`. MaterCMS хранит стабильные ID, раскрывает связанные записи в read-only API на один уровень и безопасно очищает ссылки при удалении записи. Подробная инструкция находится в `DOCUMENTATION.md`.

- Record modals use fullscreen layout only on mobile; desktop keeps compact centered dialogs.


### Интерфейс установки

Первый шаг установки приведён к широкоформатному минималистичному стилю экрана авторизации: без тяжёлой панели мастера и крупных вложенных карточек.

- авторизация и первый запуск имеют полноценный responsive `100dvh` layout со sticky бренд-зоной и отдельной прокруткой рабочего содержимого на desktop;
- экран входа теперь завершён для desktop / laptop / tablet / phone / landscape: при ширине до `960px` он становится одной центрированной колонкой без пустой области справа;
- короткие экраны используют естественный vertical scroll, а мобильная шапка адаптируется к landscape и safe-area;
- на телефонах поля авторизации сохраняют стабильные `16px`, поэтому Safari не увеличивает страницу при фокусе.


### Исправление поиска

Универсальный поиск автоматически закрывается после открытия результата, при обычной SPA-навигации и при Back/Forward; поздние ответы старых поисковых запросов игнорируются.

### Settings 03 split and interface refinement (2026-09-09)

- `Проекты` and `Команда` are separate settings pages; the old intermediate “Проекты и команда” page is removed.
- Projects owns membership management, roles and permission overrides; Team is an account directory only.
- Settings/Projects/Team use compact cards instead of stretched full-width strips on widescreen displays.
- Authentication switches to a centered single-column layout on medium desktop widths to prevent clipped/dead columns.
- Installer typography and controls were enlarged for normal 1:1 desktop scaling.
- Smart context menu uses the same floating surface language as the rest of MaterCMS.

### Project-owned access model (2026-09-09)

- Create/Edit User now edits identity only: name, email and password.
- Project membership, role and permission overrides are managed only in `Настройки → Проекты`.
- The Projects page contains a project selector plus the complete member/role editor.
- Switching the selected project while managing access keeps the user on the Projects page and reloads its members.
- Deleting a user still removes that account from its project memberships without deleting project content.

### Content clipboard (2026-09-09)

- В **Мой контент** папка или раздел на desktop выбираются одним кликом и открываются двойным кликом; на touch-устройствах обычный тап по-прежнему открывает объект.
- `Ctrl/Cmd+C` копирует выбранный объект, а `Ctrl/Cmd+V` создаёт его копию в открытой папке. Функция «Вырезать» удалена из MaterCMS.
- Те же действия доступны через context menu; у папки есть действие **«Вставить в папку»**.
- Копирование папки создаёт глубокую копию всей вложенной структуры и разделов. Файлы в полях переиспользуются безопасно через существующие ссылки, поэтому физические upload-файлы не дублируются без необходимости.
- Буфер сохраняется в рамках вкладки и может использоваться после перехода между папками и даже между доступными проектами.
- При совпадении имён MaterCMS автоматически создаёт безопасное уникальное имя, а копирование папки внутрь самой себя или дочерней папки блокируется.
- Тёмная тема API-панелей дополнительно защищена от светлых «утечек» на карточках проекта и AI Prompt.

## 2026-09-10 — «Мой контент»: функции ОС в дизайне MaterCMS

Раздел **Мой контент** сохраняет привычную модель файлового менеджера для поведения папок и разделов, но визуально остаётся частью MaterCMS. Windows-подобные операции работают через context menu, мышь и клавиатуру без копирования интерфейса Проводника.

- один клик выбирает объект, `Ctrl/Cmd` добавляет/убирает из выделения, `Shift` выбирает диапазон, `Ctrl/Cmd+A` выбирает всё;
- двойной клик или `Enter` открывает, `Ctrl/Cmd+Enter` открывает выбранный объект в новой вкладке;
- `Ctrl/Cmd+C`, `Ctrl/Cmd+V` — копирование и вставка; `Ctrl/Cmd+D` — быстрая копия;
- drag & drop создаёт копию выбранных объектов в целевой папке; исходные объекты остаются на месте;
- `F2` переименовывает, `Delete` отправляет в корзину, `Shift+Delete` удаляет без возможности восстановления;
- есть полноценная **Корзина** с восстановлением, удалением выбранного и полной очисткой; удалённый контент не попадает в публичный API;
- `Ctrl/Cmd+Z` и `Ctrl/Cmd+Y` / `Ctrl/Cmd+Shift+Z` отменяют и повторяют поддерживаемые действия: переименование, копирование и отправку в корзину;
- `Ctrl/Cmd+Shift+N` создаёт папку, `Alt+Enter` открывает свойства, `F5` обновляет, `Alt+← / → / ↑` работают как навигация проводника;
- стрелки, `Home`, `End`, `Backspace`, `Shift+F10`/клавиша контекстного меню поддерживают работу без мыши;
- сортировка по имени, типу и дате через dropdown, направления ASC/DESC, Grid/List, обычные MaterCMS breadcrumbs, постоянная контекстная toolbar-панель и компактный статус буфера;
- «Копировать путь», «Свойства», «Инвертировать выделение», «Открыть в новой вкладке» доступны там, где это уместно;
- `Ctrl/Cmd+F`, `Ctrl/Cmd+E`, `Ctrl/Cmd+K` и `F3` открывают существующий универсальный поиск MaterCMS — отдельный поисковик для папок не создаётся;
- обычный системный clipboard текста не перехватывается внутри `input`, `textarea`, `contenteditable` и при выделенном тексте.

MaterCMS заимствует только привычное поведение файлового менеджера там, где оно полезно для CMS. Визуальный язык остаётся собственным: карточки, breadcrumbs, кнопки, состояния выделения и адаптив соответствуют остальному интерфейсу MaterCMS.

### Связанные данные и формы в «Мой контент»

Через **Мой контент → Создать → Данные / Форма** можно добавить в текущую папку уже существующие ресурсы проекта. Выбор выполняется через модальное окно с checkbox. MaterCMS хранит только связь с исходным `data_set` или `form`, поэтому никакого дублирования нет: название, содержимое, API-состояние и дальнейшие изменения всегда берутся из оригинального ресурса. Один и тот же ресурс можно связать с несколькими папками.

Folder API также учитывает такие связи: в дереве появляются `data_sets` и `forms`. В режиме **Только данные** они возвращаются как информационная структура без содержимого, а в **Полном ответе** связанные данные содержат `data`, а формы — актуальную схему и сообщение успешной отправки.


### Исправление связей Data/Form

Исправлено сохранение связанных **Данных** и **Форм** в «Мой контент» на SQLite/PostgreSQL. Внутренний `insertIgnore()` теперь использует нативный синтаксис каждой СУБД и больше не строит неверный `ON CONFLICT` по всем вставляемым колонкам.

### Linked resources behave like real content items

Связанные **Данные** и **Формы** в «Мой контент» участвуют в общей desktop-модели MaterCMS: их можно выделять, копировать, вставлять в другие папки, копировать drag & drop, открывать через context menu и смотреть свойства. Создаётся только новая связь — исходный Data Set или Form остаётся единственным источником истины.

Удаление такой карточки убирает только связь из текущей папки и никогда не удаляет исходные Данные/Форму. `Ctrl+Z / Ctrl+Y` поддерживают удаление и восстановление связей.

### Production hardening

MaterCMS сам проверяет сервер при первом запуске: PHP, PDO-драйверы и права на каталоги. Необязательные `mbstring`, OPcache и APCu имеют безопасные fallback. Миграции схемы теперь выполняются только при смене версии схемы, public API не открывает PHP-сессию, admin API освобождает session lock после авторизации, SQLite использует WAL + `synchronous=NORMAL`, а JSON API по умолчанию отдаёт compact JSON (`?pretty=1` — форматированный режим для диагностики).

## Git commit message

MaterCMS хранит текущую строку для `git commit -m` сразу в двух синхронных файлах:

- `/commit.md` — в корне репозитория;
- `/cms/commit.md` — внутри папки CMS.

Оба файла всегда содержат **одну и ту же единственную строку** и полностью перезаписываются при каждом релизе. История версий и подробный changelog хранятся только в `VERSION.md`.

Текущий commit message:

```text
chore(git): keep commit message in root and cms
```

Windows CMD:

```bat
set /p COMMIT_MSG=<commit.md
git commit -m "%COMMIT_MSG%"
```

Если Git запускается из каталога `cms`, можно использовать `cms/commit.md` относительно корня либо локальный `commit.md` внутри `cms`.

## Git commit message

Файл `commit.md` в корне проекта предназначен **только для текущего Git commit message**. Он всегда содержит одну короткую строку, пригодную для `git commit -m`. При каждом следующем изменении MaterCMS файл полностью перезаписывается. История релизов и подробный changelog остаются в `VERSION.md`.

Пример для Windows CMD:

```bat
set /p COMMIT_MSG=<commit.md
git commit -m "%COMMIT_MSG%"
```

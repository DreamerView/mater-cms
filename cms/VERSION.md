Текущая версия: **2026.09.11.20**

Формат версии: `YYYY.MM.DD.N`, где `N` — порядковый номер сборки MaterCMS за день.

Начиная с версии **2026.09.10.3**, при каждом изменении проекта обязательно синхронно обновляются:

- `README.md` — краткое описание актуальных возможностей;
- `DOCUMENTATION.md` — подробное руководство и техническое поведение;
- `VERSION.md` — история изменений по версиям;
- `commit.md` и `cms/commit.md` — синхронные файлы с одной текущей строкой для `git commit -m`.

## 2026.09.11.18 — Desktop authentication visual balance

### Авторизация / Desktop polish

- Исправлено визуально неудачное состояние авторизации на типичных Windows-ноутбуках с масштабированием интерфейса, где CSS viewport попадал в промежуточный breakpoint.
- Desktop-сетка теперь сохраняет более ровную пропорцию `42 / 58`, поэтому левая продуктовая панель не выглядит случайно зажатой, а правая зона не создаёт чрезмерную пустоту.
- Максимальная ширина формы уменьшена до `440–460px` в зависимости от desktop breakpoint: поля, заголовок и security note образуют более цельную композицию.

- На tablet/mobile компактный wordmark по-прежнему явно включается обратно и сохраняет sticky/safe-area поведение.
- В продуктовой панели возвращён спокойный нижний footer `MaterCMS · Ваш контент остаётся вашим`, чтобы большая desktop-плоскость выглядела завершённее без перегрузки интерфейса.

## 2026.09.11.16 — Mobile Safari and modal hardening

### iOS input stability

- Все текстовые `input`, `textarea` и `select` на mobile используют стабильный `16px`, поэтому Safari не выполняет автоматический zoom при фокусе.
- MaterCMS не запрещает ручное масштабирование страницы и не использует `user-scalable=no`.
- Размер шрифта поля не меняется между normal/focus состояниями.

### Post / Redirect / Get

- Авторизация после любого POST завершается `303 See Other` и чистым GET.
- Установщик, выбор/сброс базы и создание первого администратора также переведены на PRG.
- Ошибки формы передаются через session flash; DB password, connection URL и пользовательские пароли в flash не сохраняются.
- Устранено системное предупреждение браузера о повторной отправке формы после refresh.

### Full-screen modals

- Добавлен общий mobile fullscreen contract на `100dvh`.
- Исправлен `database-switch`: backdrop больше не оставляет внешний padding вокруг `100vw/100dvh` modal.
- Full-screen cards работают как flex-column; header/footer фиксированы внутри поверхности, прокручивается только содержимое.
- Добавлены `safe-area-inset-top/bottom`, `overscroll-behavior` и iOS momentum scrolling.
- Унифицированы record editor, relation picker, product documentation, user editor и file preview.
- При открытой модалке фон страницы больше не прокручивается.

### Проверки

- PHP syntax check для всего `cms`.
- `node --check` для `app.js` и `ui.js`.
- CSS structure и ZIP integrity.

## 2026.09.11.9 — Smart Skeleton Loading Manager

### Navigation

- Удалена фиксированная пауза `250 ms` перед SPA-переходами.
- Route и серверная загрузка теперь стартуют немедленно.

### Architecture

- Добавлены `routeSkeletonKind` и route-aware loading lifecycle.
- Удалена зависимость UX от искусственного route delay.
- Loading Manager не блокирует начало backend-запроса.

## 2026.09.10.16 — Simplified Folder API model

### Folder API

- Удалены пользовательские настройки глубины рекурсии, отдельного `include_data` и ручного выбора веток дерева.
- Folder API теперь всегда раскрывает всю включённую структуру рекурсивно.

### Кеширование

- Единственная отдельная настройка Folder API — TTL готового JSON: off / 30 s / 1 min / 5 min / 15 min / 1 h.
- Cache key разделяет `STRUCTURE` и `FULL`, поэтому компактный и полный варианты кешируются независимо.
- Добавлен заголовок `X-MaterCMS-Tree-Content: STRUCTURE|FULL`.

## 2026.09.10.7 — Nginx-safe public API routing

### API routing

- Исправлен `404 Not Found` от nginx для public API URL вида `/cms/api/{project}/...`.
- Добавлен единый генератор public API URL: `public_api_path()` / `public_api_absolute_url()`.
- В режиме `auto` MaterCMS использует clean rewrite URL только на Apache/LiteSpeed, где `.htaccess` реально поддерживается.
- На nginx, Caddy, PHP built-in server и неизвестных web-серверах MaterCMS автоматически генерирует прямой endpoint `api/index.php?path=...`, который не требует rewrite-конфигурации.
- Все endpoint в разделах, данных, формах, API offcanvas, AI Prompt, admin state и ссылках внутри самого public API переведены на единый маршрутизатор.
- `lang`, `meta=1` и `meta=0` продолжают работать поверх direct endpoint через обычные query parameters.
- В `config.php` добавлен `api_route_mode = auto`; при необходимости можно явно выбрать `pretty` или `direct`.
- Исправлены `forms_url` и `data_url` корневого API проекта в direct-режиме: они больше не формируются конкатенацией после `?path=`.

### Совместимость

- Apache/LiteSpeed сохраняют прежние красивые URL без изменений.
- Nginx больше не требует отдельного rewrite только ради работы API; MaterCMS показывает и копирует рабочий direct URL автоматически.
- Старый вручную введённый pretty URL на nginx всё ещё требует nginx rewrite на уровне сервера — это ограничение самого nginx, а не PHP.

### Проверки

- Direct router проверен локальным HTTP-запросом: запросы к `api/index.php?path=...` доходят до PHP API-контроллера и возвращают JSON, а не web-server 404.
- PHP и JavaScript прошли синтаксическую проверку.
- Обновлены `README.md`, `DOCUMENTATION.md` и `VERSION.md`.

## 2026.09.10.3 — API response control + bottom dock

### API

- Добавлена серверная настройка проекта **«Полный ответ API»**.
- Настройка хранится в `project_settings` под ключом `api_response` и не зависит от браузера.
- В admin state и Settings API добавлено состояние `api_response`.
- Добавлен защищённый admin action `set_api_response`; изменение требует `settings.edit`.
- Компактный режим:
  - GET разделов/данных возвращает чистый object/array;
  - успешный POST формы возвращает `ok` и `message`.
- Полный режим:
  - GET разделов/данных возвращает `{ data, meta }`;
  - успешный POST формы дополнительно возвращает `submission_id`, `project`, `form`.
- `?meta=1` принудительно включает полный ответ для конкретного запроса.
- `?meta=0` принудительно включает компактный ответ для конкретного запроса.
- Public API отправляет `X-MaterCMS-Response-Mode: full|data`.
- Корневой project API сообщает `response_mode` и остаётся картой endpoint проекта.
- Новые и существующие проекты автоматически получают безопасный default `full_response=false`.

### API offcanvas

- Во все API offcanvas добавлен единый переключатель формата ответа проекта.
- Добавлен всегда закрытый по умолчанию spoiler **«Какой ответ вернёт API»** с JSON-примером.
- Для разделов preview учитывает `Object/Array`, `data + meta` и i18n.
- Для данных preview учитывает `Single/Multiple` и полный/компактный режим.
- Для форм preview показывает фактическую структуру успешного POST-ответа.
- AI Prompt синхронизирован с серверным форматом ответа и больше не описывает другую JSON-структуру.
- В prompt формы отдельно передаются JSON запроса и JSON успешного ответа.
- Верхние карточки API-панелей собраны через единый `gap`, без конфликтующих margin.

- Dock больше не выглядит как панель, плавающая над контентом.
